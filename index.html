Verification Commands

Boot a Ubuntu Server 24.04 USB stick on the machine before paying. Run each command, tick it off, and compare against the expected output. If the vendor won't let you test, walk away.

1 CPU — confirm the chip
lscpu | grep "Model name"
# Expected: Intel(R) N100 / N150  —or—  AMD Ryzen 7 5700U
2 RAM — capacity & speed
free -h
sudo dmidecode -t memory | grep -E "Size|Speed|Type"
# Expected: 8/12/16GB, DDR4-3200 or DDR5-4800
# Watch for: soldered RAM (no SO-DIMM slot = no upgrade)
3 Storage — capacity & brand
lsblk -o NAME,SIZE,TYPE,MOUNTPOINT
# Expected: advertised capacity
# Note: is it Samsung / WD / Kingston, or a no-name SSD?
4 GPU — transcoding support
lspci | grep -i vga
# Intel: Alder Lake-N [UHD Graphics]
# AMD:   Radeon Vega 8
5 Network — Ethernet ports
ip link show
# Expected: at least one eth0, ideally 2.5G
# Red flag: Wi-Fi only, no Ethernet
6 BIOS — Secure Boot toggle
sudo mokutil --sb-state
# Or: reboot, press DEL / F2, check Secure Boot is toggleable
# Required for Ubuntu Server on some OEM boards

🚩 Red flags — walk away if any of these are true

  • Specs don't match lscpu or free -h output
  • No-name SSD with no brand marking on the label
  • Soldered RAM with no SO-DIMM slot (can't upgrade later)
  • Wi-Fi only, no Ethernet port at all
  • BIOS locked — can't disable Secure Boot
  • Vendor refuses to let you boot a USB stick
  • Price for a branded 16/512 box exceeds €180

  • Cash (RMB) gets better prices than WeChat Pay at some stalls. Bring both, and don't show your full wallet.

Prerequisites

This chapter picks up after you've bought the mini PC and the 4TB USB HDD. It takes you from first boot to a working media server with a Netflix-style catalog, on-demand downloads, and wireless TV streaming.

Phase 1

OS Installation

Get Ubuntu Server 24.04 LTS onto the NVMe SSD and reachable over SSH.

1.1 · Create the USB installer

  1. Download Ubuntu Server 24.04 LTS (64-bit)

    From ubuntu.com/download/server.

  2. Write the ISO to your USB stick

    Use Rufus (Windows), balenaEtcher (Mac/Linux), or dd:

    dd Write ISO to USB 
    sudo dd if=ubuntu-24.04-live-server-amd64.iso of=/dev/sdX bs=4M status=progress oflag=sync
# Replace /dev/sdX with your USB device — check with lsblk FIRST
    ⚠️
    Wrong device = data loss. Run lsblk before the dd command and confirm your USB stick's device name.

1.2 · BIOS configuration (critical)

  1. Enter BIOS

    Press DEL, F2, F7 or ESC during boot (varies by vendor; GMKtec/Beelink usually use DEL or F7).

  2. Disable Secure Boot

    Security tab → Secure Boot → Disabled (or Custom). Ubuntu Server 24.04 sometimes fails to boot with it enabled on N100 boards.

  3. Enable UEFI boot mode

    Ensure boot mode is UEFI, not Legacy/CSM.

  4. Set USB as first boot device

    Then save and exit (usually F4 or F10).

  5. Enable Intel VT-x

    If present — for Docker virtualization support.

🔒
Some mini PCs have locked BIOSes. If you cannot disable Secure Boot, try the latest Ubuntu Server ISO — newer ISOs often ship signed kernels that work with Secure Boot enabled.

1.3 · Run the installer

  1. Boot from USB

    Select "Try or Install Ubuntu Server".

  2. Language & keyboard

    English, your layout.

  3. Network

    Ethernet auto-configures. On Wi-Fi, pick your network and enter credentials.

  4. Storage

    Use the entire NVMe SSD — not the USB HDD (that comes later). Choose "Use an entire disk".

  5. Create your user

    e.g. media. This gets UID 1000 — the same UID we use for all Docker containers.

  6. OpenSSH

    ✅ Enable — you'll use SSH for the rest of the setup.

  7. Snaps

    Skip / install none — we don't need them.

1.4 · First login & update

01 Update the system 
sudo apt update && sudo apt upgrade -y
sudo apt install -y curl wget nano htop
📶
Wi-Fi note: if you need to reconfigure Wi-Fi later, edit /etc/netplan/50-cloud-init.yaml and run sudo netplan apply. The iwlwifi driver is built into the kernel and detects Intel Wi-Fi 6 adapters automatically.
Phase 2

Media Drive Preparation

Format the 4TB USB HDD as ext4 and mount it at /mnt/media. Single filesystem = hardlinks work.

2.1 · Identify & format

02 List block devices 
lsblk
# Look for ~3.6T — e.g. /dev/sda. Do NOT touch /dev/nvme0n1 (your SSD).
03 Format as ext4 
sudo mkfs.ext4 /dev/sdX1
# Replace /dev/sdX1 with the actual partition (e.g. /dev/sda1).
# Ignore any preloaded software on the drive — you're wiping it.

2.2 · Mount permanently

04 Get the UUID 
sudo blkid /dev/sdX1
/etc/fstab 
# add this line, replacing UUID=xxxx with your actual UUID
UUID=xxxx /mnt/media ext4 defaults,noatime 0 2
05 Create mount point & mount 
sudo mkdir -p /mnt/media
sudo mount -a
# Verify it mounted:
df -h /mnt/media

2.3 · Create the directory layout

06 Create media folders 
sudo mkdir -p /mnt/media/{movies,tv,incomplete,complete,torrents}
sudo chown -R 1000:1000 /mnt/media
🔗
Why this layout? qBittorrent downloads to /data/incomplete, moves finished files to /data/complete, and Sonarr/Radarr create hardlinks into /data/movies and /data/tv. Hardlinks only work when both paths are on the same filesystem — that's why the single /mnt/media mount matters.
Phase 3

Docker Installation

Install Docker Engine and grant your user access to the Docker socket.

07 Install Docker Engine 
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# Log out and back in (or run: newgrp docker) for the group change to apply.
08 Verify Docker & Compose 
docker run hello-world
# Hello from Docker!

# Compose v2 ships with Docker Engine — no separate install needed.
Phase 4

ProtonVPN + Tailscale Keys

You need two secrets before deploying the stack. Neither is committed to Git.

4.1 · ProtonVPN WireGuard private key

  1. Log in to protonvpn.com

    Account → Account Settings → WireGuard configuration.

  2. Download a config

    Pick Netherlands (or any country you prefer).

  3. Copy the PrivateKey = value

    You'll paste it into .env in Phase 5.

4.2 · Tailscale auth key

  1. Open the keys page

    login.tailscale.com/admin/settings/keys → Generate auth key.

  2. Configure the key

    Description mediabox · Reusable ✅ Yes · Ephemeral ❌ No · Expiry: long (e.g. 90 days) or never.

  3. Copy the key

    It starts with tskey-auth-... — paste it into .env.

Troubleshooting

Gluetun won't connect

17 Gluetun logs 
docker logs gluetun --tail 100
  • Wrong WireGuard private key
  • ProtonVPN plan doesn't support WireGuard (paid plans do)
  • SERVER_REGIONS doesn't match available servers

qBittorrent WebUI not reachable

  • Use http://<mini-pc-IP>:8081 — not :8080
  • Confirm qBittorrent shares Gluetun's network namespace:
18 Check network mode 
docker inspect -f '{{.HostConfig.NetworkMode}}' qbittorrent
# should output: service:gluetun

Port forwarding keeps changing

ProtonVPN's forwarded port changes on every Gluetun restart. You can either update qBittorrent manually after each restart, or automate the sync.

⚠️
Third-party helper. The container below is community-maintained (not official) and needs your qBittorrent password in plaintext env. Use only if you're comfortable with that.
docker-compose.yml — optional port-sync service 
  port-sync:
    image: adxglock/qb-port-sync:latest
    container_name: port-sync
    network_mode: service:gluetun
    environment:
      QBITTORRENT_USERNAME: admin
      QBITTORRENT_PASSWORD: your_password
    volumes:
      - ./gluetun:/tmp/gluetun:ro
    restart: unless-stopped

Hardware transcoding not working

  • Verify the GPU is visible (ls -la /dev/dri → renderD128 + card0)
  • Check the render group ID (getent group render)
  • Ensure the Jellyfin container has the right group_add and device mount
  • In Jellyfin, confirm Dashboard → Playback → Transcoding shows Intel QuickSync (QSV)

Hardlinks not working (files are copied)

19 Confirm same filesystem 
df /mnt/media/complete /mnt/media/tv
# Both should show the SAME filesystem.
  • Enable "Use Hardlinks instead of Copy" in Sonarr/Radarr
  • Confirm the volume mount is /mnt/media:/data (one mount, not separate ones)

Home Voice Assistant — Kiosk Setup

The second build project: turn the Redmi Pad SE into a wall-mounted Home Assistant dashboard with hands-free voice control. Kiosk Satellite is free, fully local, and subscription-free — the wake word runs on-device.

Hub · MUST
Home Assistant Green (or any HAOS host)
Tablet · MUST
Android 8+ · 4GB+ RAM
Cloud · NONE
All local — no Nabu Casa subscription
Voice pipeline · REQUIRED
Piper (TTS) + openWakeWord + local STT
📦
Two halves to this build: configure the Home Assistant hub first (no tablet needed — do it before the trip), then set up the tablet (~10 min, APK only, no Play Store or Google account required).

🛠 Part A · On the Home Assistant hub

Do this before the trip — it needs no tablet.

  • Install the Wyoming add-ons: Settings → Add-ons → Add-on store → Piper (TTS), openWakeWord, and wyoming-onnx-asr (STT). On the Green's modest hardware, onnx-asr/Parakeet is noticeably lighter than faster-whisper.
  • Build a local Assist pipeline: Settings → Voice assistants → Add assistant → pick local STT + Piper + openWakeWord. Everything stays on the LAN — no Nabu Casa subscription.
  • Install HACS: Settings → Apps → add repository github.com/hacs/addons → install "Get HACS" → restart Home Assistant.
  • Install Voice Satellite: HACS → Custom repositories → add jxlarrea/voice-satellite-card-integration → download → restart. (With Kiosk Satellite's built-in voice you can skip this — but installing it costs nothing and covers both setups.)

📱 Part B · On the tablet

~10 minutes · APK only, no Play Store or Google account needed (works fine on Chinese ROMs)

  • Create a long-lived access token: HA → your profile → Security → Long-lived access tokens → copy it somewhere safe.
  • Sideload Kiosk Satellite: download the APK from the project's GitHub releases page; allow "install from unknown sources" once when prompted.
  • Run the setup wizard: enter your HA URL (http://homeassistant.local:8123) + the token → pick your dashboard → leave Voice Satellite enabled → choose wake word (e.g. "Okay Nabu") and the local pipeline.
  • Confirm discovery: the tablet shows up under Settings → Devices & services on the Green → assign it to a room/area.
  • Enable the ESPHome connection in the app settings → screen, volume, motion, and battery become HA entities you can automate.
  • Kill battery restrictions: Xiaomi/HyperOS → Settings → Apps → Kiosk Satellite → Battery saver → No restrictions. Otherwise Android will freeze the wake word overnight.
  • Protect the battery: automation on the smart plug — OFF at 80%, ON at 20% (uses the battery sensor from the step above).
